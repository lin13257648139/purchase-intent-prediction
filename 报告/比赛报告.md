## 摘要

本项目基于天猫平台用户行为日志，构建「用户—商品」采购意向预测模型，目标是在给定历史行为的前提下，识别未来 2 天内可能产生购买行为的用户—商品对。项目完整覆盖数据探索、清洗与特征工程、多模型训练与 AUC 加权集成、SHAP 可解释性分析，以及竞赛级可视化看板与 HTML 决策系统。

在严格时间切分（特征窗口 day≤17，标签窗口 day 18–19）与类别不平衡处理（负采样 1:15 + SMOTE）条件下，集成模型 **Ensemble 融合** 取得 **AUC = 0.9145**，优于单一基模型 CatBoost（AUC = 0.9107）。项目共输出 **16 张分析图表**、**1 份交互式决策看板** 及完整可复现代码。

## 一、项目背景与目标

### 1.1 业务背景

互联网平台采购场景中，用户从浏览到最终购买往往经历多步行为链路。精准预测采购意向，有助于：

- 提前识别高意向用户，优化推荐与触达策略；
- 降低无效曝光，提升转化效率；
- 为运营决策提供数据支撑。

### 1.2 项目目标

1. 对约 **1225 万条** 用户行为记录进行清洗与探索性分析；
2. 构建 **68 维** 行为特征体系，刻画用户、商品、品类及交互模式；
3. 训练 LightGBM、XGBoost、CatBoost、MLP 四类模型，并通过 **AUC 加权 Stacking** 融合；
4. 输出可视化图表与项目报告，形成可演示、可复现的完整作品。

### 1.3 技术栈

| 类别 | 工具 / 框架 |
|------|-------------|
| 语言 | Python 3 |
| 数据处理 | pandas、numpy |
| 机器学习 | LightGBM、XGBoost、CatBoost、scikit-learn |
| 不平衡处理 | SMOTE（imbalanced-learn） |
| 可解释性 | SHAP |
| 可视化 | matplotlib、seaborn、Chart.js（HTML 看板） |

## 四、数据处理与特征工程

### 4.1 数据清洗

清洗流程由 `data_utils.py` 统一实现，在 `02_高级特征工程.py` 中分块调用：

| 步骤 | 说明 |
|------|------|
| 行为合法性过滤 | 剔除 behavior_type 不在 {1,2,3,4} 的记录 |
| 品类缺失处理 | 关联商品表补全 item_category |
| 时间字段 enrich | 提取 day、hour、weekday、is_weekend |

**清洗结果**（特征窗口 day≤17）：

| 指标 | 数值 |
|------|------|
| 原始记录 | 7,137,379 条 |
| 非法行为剔除 | 0 条 |
| 有效记录 | 7,137,379 条 |
| 分块数 | 41 块 |

### 4.2 时间切分策略

为避免数据泄露，采用严格的时间划分：

| 窗口 | 范围 | 用途 |
|------|------|------|
| 特征窗口 | day ≤ 17 | 构建用户/商品/交互特征 |
| 标签窗口 | day 18–19 | 定义是否购买（正样本标签） |

### 4.3 采样策略

| 参数 | 设置 |
|------|------|
| 用户—商品对总数 | 2,759,919 对 |
| 标签期正样本 | 1,157 对 |
| 建模正样本 | 280 条 |
| 负样本池 | 2,759,639 条 |
| 负采样数量 | 4,200 条 |
| 正负比例 | 1 : 15 |
| SMOTE | 仅对训练集过采样，验证集保持原始分布 |
| 验证划分 | 分层 hold-out 80 / 20，random_seed = 42 |

### 4.4 特征体系（68 维）

| 特征组 | 维度 | 说明 |
|--------|------|------|
| 用户—商品交互 | 9 | 交互次数、转化率、最近行为间隔等 |
| 用户核心特征 | 13 | 行为统计、日均活跃、转化漏斗 |
| 多时间窗口 | 12 | 1 / 3 / 7 天滑动窗口行为计数 |
| 时间衰减 | 5 | 基于半衰期（5 天）的牛顿冷却加权 |
| 商品特征 | 8 | 热度、购买率、加购率等 |
| 品类特征 | 5 | 品类购买率、多样性等 |
| 交叉特征 | 8 | 用户×商品×品类协同信号 |
| 协同过滤 | 8 | 相似行为模式衍生特征 |

特征名称详见 `可视化图表/feature_names.json`，特征矩阵保存为 `可视化图表/features.npz`。特征工程全流程耗时约 **8005 秒（约 2.2 小时）**。

### 4.5 核心方法创新

1. **时间衰减权重**：近期行为权重更高，刻画兴趣衰减；
2. **多时间窗口统计**：捕捉短期冲动与中期偏好；
3. **转化漏斗特征**：收藏/加购到购买的链式转化率；
4. **SMOTE 过采样**：缓解正样本稀缺问题；
5. **全量分块增量聚合**：在 713 万条记录上完整聚合，非随机截断。

## 五、模型训练与集成

### 5.1 基模型配置

| 模型 | 说明 |
|------|------|
| LightGBM | 梯度提升树，class_weight=balanced |
| XGBoost | scale_pos_weight 自适应正样本权重 |
| CatBoost | 类别特征友好，鲁棒性强 |
| MLP | 全连接神经网络，捕捉非线性组合 |

### 5.2 模型性能（验证集）

| 模型 | AUC | F1 | Precision | Recall | Accuracy |
|------|-----|-----|-----------|--------|----------|
| LightGBM | 0.8974 | 0.4341 | 0.3836 | 0.5000 | 0.9185 |
| XGBoost | 0.9099 | 0.4632 | 0.5641 | 0.3929 | 0.9431 |
| CatBoost | 0.9107 | 0.5000 | 0.5682 | 0.4464 | 0.9442 |
| 神经网络 (MLP) | 0.7983 | 0.3894 | 0.3860 | 0.3929 | 0.9230 |
| **Ensemble 融合** | **0.9145** | **0.4848** | **0.5581** | **0.4286** | **0.9431** |

> 数据来源：`可视化图表/final_results.json`，模型训练耗时约 **21 秒**（在 features.npz 已生成前提下）。

**结果解读**：

- **AUC** 是本次任务的核心排序指标，集成模型达到 **0.9145**，较最优单模型 CatBoost 提升 **0.0038**；
- 正样本极少导致 **F1 / Recall** 绝对值偏低，但集成后在 Precision 与 AUC 上均取得最优或接近最优表现；
- MLP 在本任务中弱于树模型，可能因样本规模与特征稀疏性导致，仍作为集成分支提供多样性。

### 5.3 AUC 加权 Stacking 融合

第二层融合采用 **AUC 加权平均**：

```
w_i = AUC_i / Σ(AUC_j)
P_ensemble = Σ(w_i × P_i)
```

各基模型权重（按验证集 AUC 计算）：

| 模型 | AUC | 融合权重 |
|------|-----|----------|
| LightGBM | 0.8974 | 25.5% |
| XGBoost | 0.9099 | 25.9% |
| CatBoost | 0.9107 | 25.9% |
| MLP | 0.7983 | 22.7% |

### 5.4 可解释性分析（SHAP）

利用 SHAP 值分析特征对预测结果的贡献，识别 Top 特征（如用户—商品交互频次、加购率、时间衰减权重等），为业务侧理解模型决策提供依据。

## 九、结论与展望

### 9.1 项目结论

1. 完成了从原始日志到采购意向预测的 **端到端大数据建模流程**；
2. 通过 68 维特征与 AUC 加权集成，集成模型 AUC 达到 **0.9145**；

4. 代码模块化、配置集中、路径自动解析，具备良好的 **可复现性**。

### 9.2 不足与改进方向

| 方向 | 说明 |
|------|------|
| 样本规模 | 建模阶段采用负采样，可探索更大规模训练以提升 Recall |
| 模型调参 | 可引入 Optuna 等自动调参进一步提升单模型上限 |
| 实时推理 | 当前为离线批处理，可扩展为在线特征服务 |
| 业务落地 | 可结合推荐系统 A/B 测试验证线上转化提升 |
